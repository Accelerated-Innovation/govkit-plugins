# Draft 0 package format

The four files this skill emits, in the exact shapes the rest of GovKit parses. The
consumers are real code and real skills, not conventions: `govkit-feature-refine` reads
these files as inputs, `govkit-feature-readiness` gates on them, `govkit-feature-map`'s
`repo_ingest.py` parses them into `features.json`, and `govkit-metrics-emit` scores package
completeness from them. Deviating from these shapes silently drops content downstream.

## Package layout

```
features/<key-or-slug>/          e.g. features/ai204_notification_digest/
  acceptance.feature
  nfrs.md
  eval_criteria.yaml
  feature_source.md
```

The directory name should carry the tracker key when one exists — `ai204_notification_digest`
derives key `AI-204` during map ingestion. With no tracker, use a kebab/snake slug of the
feature name.

Mark every file as Draft 0 in a comment or footer line, so a reader who finds the package
without its conversation knows it has not been refined.

## acceptance.feature

Full Gherkin per SKILL.md Step F6: `@feature` on the Feature line, persona intent block,
`Rule:` blocks when business rules are explicit, one delivery-phase tag plus at least one
classification tag per scenario.

```gherkin
@feature
Feature: Notification digest

  As a project owner
  I want a daily digest of workspace activity
  So that I stay informed without reading every event

  Rule: Digests contain only events the recipient may see

    @mvp @functional
    Scenario: Daily digest includes visible events only
      Given a project owner with access to project Alpha but not project Beta
      And activity occurred in both projects yesterday
      When the daily digest is generated
      Then the digest lists the Alpha activity
      And the digest contains no Beta activity

    @mvp @security
    Scenario: Revoked access removes a project from the next digest
      Given a project owner whose access to project Alpha was revoked today
      When the next daily digest is generated
      Then the digest contains no Alpha activity
```

Tag order on the line: delivery phase first, then classification tags — the same order
`govkit-feature-slice` emits, so a later slicing pass produces minimal diffs.

## nfrs.md

A markdown table. The map ingester matches columns by header name (substring,
case-insensitive), so these headers are safe: **ID, Dimension, Requirement, Threshold,
Evidence, Owner, Gap**. Order does not matter; unknown columns are ignored (Owner is kept
for refine and readiness, which check owners).

Unstated thresholds are written as `TBD — set in refinement`. The literal `TBD` matters:
ingestion flags those rows as `nfrTbd`, which is how the gap stays visible on the feature
map instead of disappearing into prose.

```markdown
# Non-Functional Requirements — AI-204 Notification digest (Draft 0)

| ID | Dimension | Requirement | Threshold | Evidence | Owner | Gap |
|---|---|---|---|---|---|---|
| N1 | Performance | Digest generation completes for a workspace of 500 projects | TBD — set in refinement | load test run in CI | TBD | threshold unset |
| N2 | Security | Digest content respects project-level permissions at send time | 0 cross-project leaks in permission test suite | permission test suite in CI | QA lead | — |
| N3 | Reliability | Digest delivery succeeds or is retried | TBD — set in refinement | delivery job metrics | TBD | threshold unset |
```

GenAI-mode features add rows for latency, token cost, model/vendor constraints,
observability, and evaluation cadence — thresholds `TBD` unless the PM stated them.

## eval_criteria.yaml

Two consumers read this file with slightly different expectations, and one file satisfies
both:

- The map ingester reads a top-level `evaluation_criteria:` list; each item's `id`, `type`,
  `rule_link`, `method`, `pass_threshold`, and `gate` land on the feature card.
- The metrics emitter reads `mode` (must be `llm`, `deterministic`, or `none`), counts
  `llm_evaluation.criteria` when mode is `llm`, and reads `unit_tests.enforce_FIRST` /
  `enforce_virtues`. Use a YAML anchor so the `llm_evaluation` mirror never drifts from the
  canonical list.

`multi_agent` appears **only** when the team explicitly answered the agentic behavior
question (SKILL.md Step F8). Unanswered means the key is absent, never `false`.

GenAI-mode template (`mode: llm`):

```yaml
# Draft 0 — generated by govkit-feature-create; thresholds marked TBD are set in refinement.
feature: AI-204
mode: llm                # llm | deterministic | none
multi_agent: false       # only from the team's explicit yes/no answer; omit if unanswered

evaluation_criteria: &criteria
  - id: EV-1
    type: groundedness
    rule_link: "Digest summaries describe only events in the digest window"
    method: "LLM-judge against a curated event/summary eval set"
    pass_threshold: "TBD — set in refinement"
    gate: pr             # pr | release | none
    tool: promptfoo      # optional
  - id: EV-2
    type: safety
    rule_link: "Digest never includes content from projects the recipient cannot see"
    method: "adversarial permission probe set"
    pass_threshold: "TBD — set in refinement"
    gate: release

# Mirror for govkit-metrics-emit (mode: llm requires llm_evaluation.criteria >= 1).
llm_evaluation:
  criteria: *criteria

unit_tests:
  enforce_FIRST: true
  enforce_virtues: true
```

Ordinary functional feature (`mode: deterministic`): drop the `llm_evaluation` block, keep
`evaluation_criteria` minimal — deterministic test evidence tied to rules is enough.

```yaml
# Draft 0 — generated by govkit-feature-create.
feature: AI-207
mode: deterministic

evaluation_criteria:
  - id: EV-1
    type: functional
    rule_link: "Digests contain only events the recipient may see"
    method: "automated acceptance tests tagged @mvp"
    pass_threshold: "all scenarios pass"
    gate: pr

unit_tests:
  enforce_FIRST: true
  enforce_virtues: true
```

## feature_source.md

Everything the other three files don't hold: stories, description, Definition of Done,
privacy, open questions, traceability. The map ingester matches sections loosely by heading
name; the headings below all land in the right buckets (`User Context`, `In Scope`,
`Out of Scope`, `Open Questions`, `Definition of Done`, `Privacy`). Keep them.

```markdown
# AI-204 — Notification digest (Draft 0)

## User Context

As a project owner, I need a daily digest of workspace activity so that I stay informed
without reading every event.

Secondary: As a workspace admin, I need digests to respect permissions so that access
revocation is effective immediately.

## Summary

<one-paragraph feature summary from Step F5>

## In Scope

- Daily digest generation per recipient
- Permission-filtered event selection

## Out of Scope

- Real-time notifications (owned by AI-206 Notification streams)
- Digest frequency preferences (V1)

## Dependencies

- Event store API (existing)
- Permission service (existing)

## Key User Flows

1. <flow>

## Definition of Done

- [ ] All @mvp scenarios pass in CI
- [ ] Security checks completed (permission test suite green)
- [ ] Evaluation thresholds in eval_criteria.yaml met (once set in refinement)
- [ ] Documentation updated

## Privacy

Processes user activity metadata (names, project titles, timestamps). Mitigations:
permission check at send time, no event payloads in digest storage, digest retention 30
days.

## Open Questions

- Digest send-time localization — per user or per workspace?

## Traceability

- Generator: govkit-feature-create (Draft 0)
- Tracker: Jira AI-204 (Epic AI-200)
- Created: 2026-08-10
- Status: Draft 0 — awaiting govkit-feature-refine
```

The Traceability block is what lets `govkit-feature-readiness` confirm "source traceability
back to the approved generator/tracker record" without archaeology. Always include
generator, tracker record (or "none — repo only"), epic link, date, and Draft 0 status.
